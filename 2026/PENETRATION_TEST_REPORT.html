Executive summary

The assessment confirmed exploitable SQL injection, insecure direct object reference, and reflected cross-site scripting. An unauthenticated client can alter product database queries, retrieve other users' orders, enumerate every order through a special identifier, and inject active HTML or JavaScript into the search response.

This application is an intentionally vulnerable localhost training lab. The severity ratings describe how these flaws would be treated in a deployed application. The tested in-memory records have no production value.

Critical

VS-01 — SQL injection in product search

Affected route GET /sqli?search=

The application concatenates the search parameter directly into a SQL statement. Client-supplied syntax is interpreted by SQLite.

Evidence

A tautology returned all four products.

' OR 1=1 --

A union query introduced a controlled result row named Injected.

' UNION SELECT 999,'Injected','Controlled row',1 --

Impact

An attacker can bypass query filters and read data available to the database connection. Depending on database permissions, the flaw may also permit modification, deletion, authentication bypass, or service disruption.

Remediation

const rows = db
  .prepare('SELECT id, name, description, price FROM products WHERE name LIKE ?')
  .all(`%${search}%`);

Use parameterized statements, least-privilege database identities, and regression tests containing quotes, comment tokens, and boolean expressions.

High

VS-02 — IDOR and unrestricted order enumeration

Affected route GET /idor?as=&order_id=

The order lookup does not verify ownership. The as parameter controls the displayed identity without trusted authentication, while order ID 0 returns every order.

Evidence

GET /idor?as=alice&order_id=2001
GET /idor?as=alice&order_id=0

Alice could read Bob's order. The enumeration request returned four receipts, including order #3001, owner meow, item Catnip, total ¥10,000, and shipping destination Yokohama.

Impact

An attacker can retrieve another user's order contents and shipping information. Sequential IDs permit targeted enumeration, while the magic zero value exposes the complete collection.

Remediation

const order = db
  .prepare('SELECT * FROM orders WHERE id = ? AND owner = ?')
  .get(Number(orderId), authenticatedUser);

Use a trusted server-side identity, remove the zero-ID behavior, and return the same generic response for nonexistent and unauthorized records.

Medium

VS-03 — Reflected cross-site scripting

Affected route GET /xss?q=

The q parameter is inserted into HTML without output encoding. The following payload was returned unchanged inside the result element.

<img src=x onerror=alert(document.domain)>

Impact

A crafted link can execute JavaScript in the VulnShop origin when opened by another user, enabling actions or data access available to the victim.

Remediation

result = `<div class="result">Showing results for
  <strong>${escapeHtml(query)}</strong></div>`;

Apply context-aware output encoding and deploy a restrictive Content Security Policy as an additional control.

Low

VS-04 — Database error disclosure

Malformed search input returns SQLite errors directly to the client. A single quote produced a visible Database error response, helping an attacker identify query parsing behavior.

Remediation

Log detailed errors on the server and return a stable generic message with an internal correlation identifier.

Informational

VS-05 — Missing browser hardening headers

The application returns X-Content-Type-Options: nosniff, but no Content Security Policy or frame-protection directive was present.

Remediation

Add a restrictive Content Security Policy after fixing the XSS sink. Use the CSP frame-ancestors directive to control framing.

Methodology

Testing included endpoint discovery, parameter manipulation, reflected-input analysis, object-level authorization checks, SQL metacharacter and union-query testing, response-header inspection, and targeted source review. All active testing was restricted to 127.0.0.1:8000 and the seeded in-memory database.

Limitations

The assessment covered the current HTTP routes and source code. Deployment infrastructure, TLS, third-party dependencies, persistence layers, and authenticated session management were outside scope because those components are absent from this local lab. Browser execution was inferred from the confirmed raw XSS response and standard HTML behavior. No external systems were tested.

Recommended remediation order

  1. Replace SQL string concatenation with parameterized statements.
  2. Implement trusted authentication and per-order ownership checks, then remove the order_id=0 behavior.
  3. Encode reflected output and deploy a restrictive Content Security Policy.
  4. Replace client-visible database errors with generic responses.
  5. Add automated regression tests for the three primary vulnerabilities.
